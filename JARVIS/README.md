# JARVIS — персональная ИИ-система

Настольное приложение для Windows 10/11 (Electron + React + TypeScript). **Готовы этапы 1–4**: ядро —
ИИ-чат, локальная история, память, настройки и безопасность; **голос** (команды, слово «Джарвис», озвучка);
**управление компьютером** (файлы, программы, браузер, снимок экрана — только с вашего разрешения);
**ИИ-программист** (проекты, правка кода, тесты, Git, субагенты). Полный план — в
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), модель безопасности — в [docs/SECURITY.md](docs/SECURITY.md).

> Проект лежит в отдельной папке `JARVIS/` и не затрагивает остальные файлы репозитория.

## Быстрый старт (Windows)

1. Установите [Node.js LTS](https://nodejs.org) (нужна версия **22.13 или новее**) и, при желании, Git.
2. Откройте папку `JARVIS` и дважды щёлкните **`start-jarvis.bat`** — он сам установит зависимости и запустит приложение.

То же самое вручную:

```powershell
cd JARVIS
npm install
npm run doctor     # проверка среды
npm start          # сборка и запуск
```

Без API-ключа приложение работает в **демо-режиме**. Чтобы подключить настоящий ИИ, откройте
«Настройки» и введите ключ Anthropic (или задайте переменную окружения `ANTHROPIC_API_KEY`).

### Положить на рабочий стол

Папка создана внутри репозитория. Чтобы работать с ней с рабочего стола, скопируйте `JARVIS` на
`Рабочий стол` (после `git pull`) — приложение не зависит от остального репозитория.

## Команды

| Команда | Что делает |
|---|---|
| `npm run doctor` | проверяет Node, npm, Git, SQLite, Electron |
| `npm start` | собирает и запускает приложение |
| `npm run dev` | режим разработки (горячая перезагрузка интерфейса) |
| `npm test` | модульные и интеграционные тесты (vitest) |
| `npm run typecheck` | проверка типов TypeScript |
| `npm run check` | типы + тесты |
| `npm run smoke` | сквозные тесты: запускают настоящий Electron (чат, безопасность, голос с поддельным микрофоном, управление компьютером), делают скриншоты |
| `npm run dist` | установщик Windows (`release/`, electron-builder) |

Данные (БД, секреты) хранятся в `%APPDATA%\JARVIS`. Для другого каталога задайте `JARVIS_DATA_DIR`.

## Что реализовано на этапе 1

- **ИИ-чат** с потоковым выводом, историей диалогов (SQLite), автоназванием, удалением.
- **Провайдеры**: Anthropic Claude (Messages API) и **демо-режим** без ключа и сети; выбор «Авто/Claude/Демо».
  Интерфейс `ChatProvider` позволяет добавлять других провайдеров.
- **Долговременная память**: предпочтения, проекты, задачи, факты — через интерфейс и по просьбе («Запомни: …»).
- **Инструменты** (`ToolRegistry`) с уровнями риска: время, чтение/запись/удаление памяти.
  Основа для файлов, браузера, CRM и обучения в следующих этапах.
- **Безопасность** (подробно в SECURITY.md):
  политика по ролям и уровням риска · окно подтверждения опасных действий (по умолчанию «Отклонить») ·
  кнопка **«Стоп»** (в чате и в окне подтверждения) · журнал действий с цепочкой хешей и запретом правки ·
  секреты шифруются средствами ОС (DPAPI) и не попадают в интерфейс · защита от инъекций из внешних данных ·
  запрет изменения «производственных» данных CRM · изолированный рендерер (sandbox, CSP, узкий IPC).
- **Настройки**: провайдер, модель, ключ, тема, порог подтверждений, свои инструкции, память вкл/выкл.
- **Тесты**: 116 модульных/интеграционных (включая настоящий Chromium, npm и Git) + четыре сквозных smoke-теста реального Electron.

## Голос (этап 2)

Как включить: **Настройки → Голос** → ключ API распознавания речи (OpenAI-совместимый; по умолчанию
`https://api.openai.com/v1`, модель `gpt-4o-mini-transcribe`) → галочка «Разрешить использование микрофона» →
кнопка **«Микрофон»** в чате.

- **Режим «по кнопке»**: нажали, сказали фразу — она распознаётся, уходит в чат, микрофон выключается сам.
- **Режим «Джарвис»**: микрофон слушает постоянно; реагирует только на фразы, начинающиеся со слова «Джарвис»
  (также «жарвис», «jarvis»…). Остальное отбрасывается. Если сказать просто «Джарвис», он ответит «Слушаю» и ждёт команду 8 с.
- **«Стоп» / «остановись» / «Джарвис, отмена»** голосом прерывают задачу и озвучку.
- **Озвучка** ответов на голосовые команды: голоса Windows (бесплатно, без ключа) или облачный синтез речи.
- **Контроль микрофона**: главный выключатель в настройках (по умолчанию выключен, на уровне ОС-разрешений
  приложения — без него доступа к микрофону нет вообще); после запуска прослушивание всегда выключено;
  красный индикатор в боковой панели и на кнопке; кнопка «выкл.»; включение/выключение пишется в журнал.
- **Безопасность голоса**: голосовая команда проходит те же политики, что и текст; **подтвердить опасное действие
  голосом нельзя** — только кнопкой в окне. В журнал пишутся длительность и размер записи, но не текст разговоров.

Важно знать: звук (и в режиме «Джарвис» — каждая услышанная фраза) отправляется выбранному сервису
распознавания и тарифицируется им. Звуки без речи отсекаются локально по громкости.

## Управление компьютером (этап 3)

**Принцип: по умолчанию у ассистента нет доступа ни к чему.** Всё разрешается вами в
**Настройки → Доступ к компьютеру** через обычные окна Windows. Ассистент (ИИ) не может расширить свои права.

| Возможность | Как работает | Подтверждение |
|---|---|---|
| **Файлы** (`fs_*`) | Только внутри добавленных вами папок. Просмотр, поиск, чтение текстовых файлов (до 256 КБ) | чтение, просмотр — без; создание/перенос/открытие — **да**; перезапись и удаление (только в Корзину) — **да, «высокий риск»** |
| **Программы** (`app_*`) | Блокнот, Калькулятор, Paint + те, что вы добавили (.exe). Без аргументов и без командной строки | **да** |
| **Браузер** (`browser_*`) | Отдельное окно Edge/Chrome со своим профилем (не вашим). Читает текст страницы и пронумерованные элементы, нажимает, вводит текст | открытие, клик, ввод — **да**; чтение — без |
| **Снимок экрана** (`screen_capture`) | Основной монитор, уходит модели | **каждый раз**, «высокий риск», с миниатюрой в чате |

Что заблокировано всегда: корень диска, системные папки, вся папка пользователя, AppData, данные самого JARVIS;
файлы `.env`, `.ssh`, `*.pem`, `*.key`, `credentials*`; запуск `.exe/.bat/.ps1/.vbs/.lnk` через «открыть файл»;
сетевые пути `\\сервер\…`; `file://`, `localhost` и локальная сеть в браузере (пока вы сами не добавите адрес,
например тестовую CRM `localhost:5173`); ввод в поля паролей, карт и одноразовых кодов — их вводите только вы;
загрузки файлов из браузера; всплывающие окна.

Многошаговые задачи: ассистент может связать до 12 шагов подряд (например, найти файл → прочитать → создать отчёт);
каждое изменение всё равно ждёт вашего «Разрешить», а «Стоп» прерывает цепочку.

Для браузера нужен установленный **Microsoft Edge** (есть в Windows 10/11) или Google Chrome — скачивать ничего не нужно.

## ИИ-программист (этап 4)

Работает внутри ваших разрешённых папок (см. выше). Попросите, например: «Создай в папке Джарвис проект node-app calc, добавь функцию
сложения и тесты, проверь, что тесты проходят, и сделай коммит».

| Инструмент | Что делает | Подтверждение |
|---|---|---|
| `project_overview`, `code_search` | анализ проекта: стек, скрипты, структура, объём; поиск по коду | нет |
| `project_scaffold` | новый проект из шаблона: `node-app` (тесты на встроенном `node:test`), `static-site` | да |
| `code_edit` | точечная правка файла (фрагмент должен быть уникальным; окно показывает «было → стало») | да |
| `run_script` | `npm run test / build / lint / typecheck / check`; вывод и код выхода возвращаются ассистенту, он исправляет и повторяет | да; окно показывает **точную команду** скрипта; подозрительная команда (curl, powershell, rm -rf, git push…) → «высокий риск» с предупреждением |
| `npm_install` | установка зависимостей, по умолчанию `--ignore-scripts` | да, «высокий риск» |
| `git_status/diff/log` | чтение состояния | нет |
| `git_init`, `git_branch`, `git_commit` | репозиторий, ветка, коммит (откажет, если среди изменений секреты — `.env`, ключи) | да |
| `git_push` | отправка текущей ветки в origin, без force | да, «высокий риск» |
| `delegate_task` | поручает задачу **субагенту**: `developer` (пишет и чинит), `tester` (запускает проверки, пишет тесты, не правит код), `reviewer` (ревью, только чтение) | действия субагента подтверждаются так же; в окне пометка «агент: …» |

Как ассистент чинит ошибки: `run_script test` → читает вывод → `code_edit` → снова тесты, до 12 шагов подряд; «Стоп» прерывает цепочку и убивает запущенные процессы.
Субагенты (до 15 шагов каждый) получают только свои инструменты, не могут делегировать дальше и не имеют `git_push`.

Безопасность запуска кода: процессы запускаются **без командной оболочки**, без доступа к вашим ключам (окружение очищено от токенов и API-ключей),
с таймаутом 3 мин, лимитом вывода и убийством всего дерева процессов; Git запускается с отключёнными хуками и `fsmonitor` (вредоносный репозиторий
не выполнит код при `git status`); запись в `.git` и `node_modules` запрещена. **Но тесты и скрипты проекта — это код с вашими правами**: они могут
сделать всё, что можете вы. Поэтому каждое выполнение требует вашего «Разрешить», а окно показывает точную команду.

## Ограничения этой версии (честно)

- CRM, обучение и телефония — следующие этапы; ассистент сам сообщает, что они недоступны.
- **Этап 4:** основной сценарий (Node.js/npm + Git) проверен автотестами и в настоящем Electron под Linux. Не проверено: запуск npm и Git на Windows
  (поиск `npm-cli.js`, убийство дерева процессов через `taskkill`), реальная работа субагентов с моделью Claude (в тестах — заглушка модели,
  поэтому качество кода и умение самостоятельно чинить сложные ошибки не оценены), `git push` на настоящий сервер.
  Субагенты в демо-режиме (без ключа Claude) недоступны. Другие стеки (Python, .NET, Docker) пока без готовых инструментов запуска; код на них можно
  читать и править, но запускать нечем. Скрипты `start`/`dev` (долгоживущие серверы) запускать нельзя. Правка файлов только текстовая и целиком в памяти (до 1 МБ).
- **Этап 3 проверен в Linux-контейнере** (настоящий Electron под Xvfb, Chromium вместо Edge). **Не проверено на Windows:**
  Корзина (`shell.trashItem`), запуск программ, выбор папок в окне Windows, Edge, снимок экрана на вашем мониторе.
- **Нет «Windows UI Automation»** (управление чужими окнами: клики по кнопкам любой программы). Ассистент умеет только
  запускать программы и работать в своём браузере. Это запланировано отдельно: нужен вспомогательный процесс и аккуратная модель прав.
- Браузер читает страницу как текст и список элементов, **картинки страниц не анализирует** (для этого есть снимок экрана);
  сложные сайты (капча, canvas-приложения, Shadow DOM) могут не работать.
- Снимок экрана — только основной монитор, весь экран целиком (без выбора окна).
- Защита адресов браузера не рассчитана на DNS-подмену (когда публичное имя указывает на локальный адрес);
  и всё равно действует подтверждение каждого клика.
- **Голос проверен на поддельном микрофоне** (wav-файл) и поддельном сервере распознавания. С реальным
  микрофоном, реальным API и русскими голосами Windows не проверялось: качество распознавания слова «Джарвис»
  зависит от выбранной модели. Нет локального (офлайн) распознавания; слово-активатор определяется по тексту
  распознавания, а не отдельным детектором, поэтому режим «Джарвис» платный и с задержкой 1–3 с.
- Свой микрофон в Windows должен быть разрешён: Параметры → Конфиденциальность → Микрофон.
- История и память в БД лежат **без шифрования на уровне файла** (защита — права учётной записи Windows/BitLocker).
  Шифрование — только для секретов.
- Демо-режим понимает несколько фраз по шаблону — это не ИИ.
- Ответы выводятся простым текстом, без Markdown-разметки.
- Работа под **Windows** (сборка установщика, DPAPI) на этом этапе не проверялась: разработка и проверка
  велись в Linux-контейнере (Electron 45 под Xvfb). Установщик `npm run dist` не собирался.
- Проверка ключа и работы Claude «вживую» не выполнялась (ключа в среде разработки нет); адаптер покрыт
  тестами только в части преобразования сообщений и обработки ошибок.
- Claude Agent SDK пока не подключён: он понадобится на этапах 4 и 8 (мультиагентность), совместимость
  с упаковкой Electron нужно проверить перед использованием.

## Совместимость (проверено при разработке)

Node.js 22.23 (локально) · Electron 45.4.1 (внутри Node 24.22, `node:sqlite` доступен) · React 19.3 ·
Vite 8.3 · Vitest 5.1 · TypeScript 7.0 · `@anthropic-ai/sdk` 1.12. SQLite — встроенный `node:sqlite`
(помечен в Node как experimental, API может измениться), поэтому нет нативной компиляции под Windows.
