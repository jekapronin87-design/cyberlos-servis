# Подключение к CRM (только чтение)

## CRM «Аквамастер» — по API-ключу (рекомендуется)

Настройки → **CRM «Аквамастер» — по API-ключу**.

1. В CRM: «Безопасность» → «API-ключи» → «Создать ключ» (название, например, «Системно», нужные разделы).
2. Скопируйте ключ сразу (CRM показывает его один раз; начинается с `sro_`). В чат его вставлять не нужно.
3. В Системно вставьте ключ, адрес CRM оставьте `https://crm.aquamaster-septiki.ru`, нажмите «Сохранить» и «Проверить подключение».

Как это устроено: клиент умеет **только GET на адреса `/api/readonly/…`** (любой другой путь отклоняется до отправки), ключ уходит заголовком `Authorization: Bearer` только на сохранённый адрес, **перенаправления не выполняются** (ключ не может уйти на чужой сайт), в базе настроек и в журнале ключа нет (хранится в зашифрованном хранилище ОС). Телефоны и почта в ответах дополнительно скрываются (можно выключить). Ключ можно отозвать в CRM в любой момент. Инструменты для ассистента и агентов: `crm_live_status`, `crm_live_index` (какие разделы открыты), `crm_live_get` (раздел, limit, даты); в агентах они входят в группу «CRM (только чтение)».

Ниже — устаревший способ для другой CRM («Сайберлос», вход по логину и паролю).

# CRM «Сайберлос» (вход по логину и паролю, только чтение)

> **Важно.** Этот способ работает только с CRM «Сайберлос» (сервер Express + Prisma, репозиторий `cyberlos-servis-Mob`). Если ваша CRM другая (например, «Аквамастер CRM» на Next.js), прямое подключение по API не получится, пока не известен её API. Пока есть способ **через браузер**: Системно открывает вашу CRM в своём окне браузера (вы один раз входите сами), читает доски и разделы как человек. Для этого есть агент «Читатель CRM через браузер» в разделе «Агенты».

JARVIS читает CRM через её обычный API (`backend/`, Express + Prisma). Он умеет **только входить и выполнять GET-запросы** к фиксированному списку путей:

| Путь | Что даёт | Нужное право в CRM |
|---|---|---|
| `GET /auth/me` | кто вошёл, роль, права | — |
| `GET /crm/pipelines` | воронки, стадии, SLA, обязательные поля | `pipeline.view_all` |
| `GET /crm/pipelines/:id/deals` | сделки/заявки | `pipeline.view_all` |
| `GET /crm/pipelines/deals/:id/history` | история сделки | `pipeline.view_all` |
| `GET /crm/tasks` | задачи сотрудников | `tasks.view_all` |
| `GET /crm/team` | сотрудники и роли | `team.view` |
| `GET /crm/production-orders` | производство | `pipeline.production.view` |
| `GET /crm/inventory` | склад | `inventory.view` |

Всё остальное (создание, перенос, удаление сделок, сообщения, роли, админка) в JARVIS **не реализовано вообще**: запросы к другим путям блокируются до отправки.
Это проверено автотестом (фиктивный сервер CRM фиксирует запросы: один `POST /auth/login`, остальное — `GET`).

## 0. Коротко: что вводить и где взять

| Поле в «Настройки → CRM» | Что вписать |
|---|---|
| **Адрес CRM** | Адрес, по которому вы открываете CRM в браузере (например `https://app.cyberlos.ru`). Если backend лежит на отдельном адресе (Railway: `https://xxx.up.railway.app`) — впишите его. Приписку `/api` программа подберёт сама. Проверка: адрес + `/health` в браузере показывает `{"ok":true}`. |
| **Если не подключается** | Программа сама ищет сервер: проверяет `/health` по адресу, по `адрес/api` и по `api.ваш-домен` (пароль на этом шаге не отправляется, только на найденный настоящий сервер). Если не нашла, но CRM в браузере работает — сервер на другом адресе. Откройте CRM → **F12** → вкладка **Network (Сеть)** → обновите страницу → щёлкните любой запрос к `/api/…` — в «Request URL» виден адрес сервера (всё до `/api`). Его и вписывайте. |
| **Логин** | Почта **отдельной** учётной записи для Системно, например `jarvis@ваш-домен.ru` (не ваша личная и не директора). Почтовый ящик может и не существовать. |
| **Пароль** | Тот, что вы зададите при принятии приглашения (шаг 1). |

Логина и пароля «готовых» нет: учётную запись вы создаёте сами, **приглашением сотрудника** в CRM — так же, как приглашаете человека.

## 1. Создайте отдельную роль и учётную запись (5 минут)

В CRM под директором/админом:

1. **Роли → Новая роль** (под директором/админом): ключ `jarvis_readonly`, название «Джарвис (чтение)». Для «доступа ко всем разделам» отметьте **все права просмотра**:
   `team.view`, `pipeline.view_all`, `pipeline.cold_leads.view`, `pipeline.dealer_acquisition.view`, `pipeline.dealer_sales.view`, `pipeline.production.view`, `inventory.view`, `tasks.view_all`, `tasks.view_own`, `worksession.view_all`.
   Права `*.manage`, `*.terminate`, `deals.bulk_*`, `tasks.assign`, `roles.manage`, `messenger.use`, `integrations.manage` — **не отмечать**: Системно умеет только читать, а лишние права на запись — лишний риск (если кто-то получит доступ к его учётной записи).
2. **Команда → Пригласить сотрудника**: почта `jarvis@ваш-домен.ru`, роль «Джарвис (чтение)» → «Пригласить». Если почта в CRM не настроена, CRM **покажет ссылку-приглашение** — скопируйте её, откройте в браузере, введите имя (например «Системно»), придумайте **пароль** (длинный, 12+ символов) и нажмите «Принять». Этот email и пароль и вводятся в «Настройки → CRM» в Системно.
3. (Если в CRM используется подтверждение почты — подтвердите её.)

Либо добавьте роль в `backend/prisma/seed-roles.ts` (после выпуска изменения — перезапустить сидирование):

```ts
{ key: "jarvis_readonly", name: "Джарвис (чтение)", permissions: [
  "pipeline.view_all", "tasks.view_all", "team.view", "inventory.view", "pipeline.production.view",
] },
```

## 2. Тестовая среда (рекомендуется начать с неё)

В CRM нет отдельного «режима обучения», поэтому тестовая среда — это **отдельная копия CRM с учебными данными** (в репозитории есть `DEPLOY.md` и `DEPLOY_RAILWAY_VERCEL.md`, `npm run seed` создаёт демо-данные). Подключите JARVIS сначала к ней
(Настройки → CRM → Окружение «Тестовое»), убедитесь, что отчёты корректны, и только потом — к рабочей.

## 3. Подключение в JARVIS

Настройки → **CRM «Сайберлос»**: адрес **бэкенда** (API), окружение, логин, пароль → «Сохранить» → «Проверить подключение».
JARVIS проверит, что у учётной записи нет прав на изменение, и подскажет, каких прав на чтение не хватает.
Пароль хранится зашифрованно (Windows DPAPI), токен — только в памяти.

## 4. Что умеет

Голосом или в чате: «Что нового в CRM?», «Какие заявки просрочены?», «Как работает Анна?», «Где узкие места в продажах?», «Что с производством и складом?».
Экран **CRM**: плитки (новые за 24 ч, без ответственного, просрочено по SLA, задачи, производство, склад), воронки по стадиям, таблица менеджеров,
замечания по работе с CRM и рекомендации по обучению.

Отчёты: `daily`, `managers`, `bottlenecks`, `quality`, `training` (инструмент `crm_report`).
Замечания (`quality`): не заполнены обязательные поля, нет следующего действия (задачи), нет ответственного, простой дольше SLA, отказ без причины,
статус не соответствует стадии, у заявки нет контактов, производство без предоплаты, просрочен срок производства.
**Это не оценка людей:** ошибки — повод предложить обучение.

## 5. Персональные данные

По умолчанию телефоны, почта и фамилии **клиентов** в данных, которые получает ИИ, маскируются (`+7 *** *** 45-67`, `Иван П.`, `i***@mail.ru`; имя клиента из карточки
вырезается и из названий сделок/комментариев). Имена **сотрудников** не маскируются — иначе нельзя анализировать их работу. Ограничение: если фамилия клиента есть
только в произвольном тексте и не указана в карточке, программа её не увидит.
Данные CRM уходят провайдеру ИИ (Claude) в составе запросов — это персональные данные: используйте рабочую CRM после проверки на тестовой и убедитесь, что это
соответствует вашим документам об обработке ПДн (152-ФЗ).

## 6. Известные ограничения

* «Время простоя» по SLA считается по `updatedAt` сделки (приближение: оно обновляется и при правке карточки); точное время перехода — в истории сделки (`crm_deal_history`).
* Смены сотрудников (`/crm/work-sessions`) в API видны только владельцу — «кто когда начал рабочий день» у JARVIS пока нет.
* Сообщения мессенджера и чаты заявок JARVIS не читает.
* Лимит анализа — 5000 сделок.
* Не проверено на вашей настоящей CRM: логика проверена на фиктивном сервере, повторяющем формы ответов из исходного кода `backend/src/routes`.
