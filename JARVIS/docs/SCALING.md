# Масштабирование JARVIS

Что уже сделано для роста, и каким путём идти дальше. Сейчас это **один пользователь и одна компания на одном компьютере**; ниже — честно, что для чего нужно.

## Уже есть (этап 10)

* **Модули с выключателями** (`src/core/modules.ts`, «Настройки → Модули»): компьютер, ИИ-программист, CRM, наставник, расписание, телефония, доступ с телефона. Выключенный модуль исчезает для модели и интерфейса и блокируется в исполнителе. Так можно ставить «только наставник + CRM» для отдела, не давая управления компьютером.
* **Роли и политика** (`security/policy.ts`): сейчас `owner` / `employee`-подобные уровни, решение зависит от риска и роли — это точка расширения для прав в компании.
* **CRM-коннектор** настраивается (адрес, окружение, учётная запись, маскирование ПДн) — подключение другой компании = другие настройки, код тот же.
* **База знаний и курсы** отделены от кода (БД + `seed.ts`/`courses.ts`): правила компании — данные, не программа.
* **Ядро без Electron** (`JarvisCore`): его можно запустить серверным процессом, это основа для сетевого режима.

## Путь к «много сотрудников»

1. **Серверный режим.** Запускать `JarvisCore` как службу (Node) на сервере компании; Electron-окно и телефон — клиенты. Шлюз (`gateway`) уже умеет сопряжённые устройства; нужно добавить TLS (за обратным прокси или встроенно), срок жизни токенов и привязку устройства к сотруднику.
2. **Пользователи и роли.** Таблицы `users` (сотрудник, роль, почта в CRM) и `user_id` в `conversations`, `memory`, `profile`, `mentor_*`, `devices`. Политика берёт роль из пользователя. Руководитель видит кабинет по подчинённым, сотрудник — только своё.
3. **Мультиарендность (разные компании).** `tenant_id` во всех таблицах (или, надёжнее, **отдельная БД и каталог секретов на арендатора**: проще изолировать и удалять). Ключи API и пароль CRM — отдельно на арендатора; журнал аудита — раздельный.
4. **Лицензирование и упаковка модулей.** Список включённых модулей хранить в лицензии арендатора (сейчас — настройка `disabledModules`); сборка «только наставник» — отдельная сборка без модулей компьютера/программиста (код модулей уже разнесён по папкам).
5. **Масштаб вычислений.** Провайдеры моделей уже за интерфейсом (`ChatProvider`); добавить очередь запросов и лимиты на арендатора. Тяжёлые задачи (субагенты, браузер) — отдельные рабочие процессы.
6. **Телефония.** Подключить оператора через `TelephonyProvider`; добавить распознавание/синтез по телефонной линии и юридические тексты согласий под вашу юрисдикцию (проверить у юриста — закон о персональных данных и о записи разговоров).
7. **Эксплуатация.** Резервные копии БД, шифрование файла БД, обновления по каналам (stable/beta — основа в `updateBranch`), мониторинг и журнал аудита в централизованное хранилище.

## Чего делать не нужно заранее

Не вводите `tenant_id` и серверный режим, пока нет второго пользователя: это усложнит каждый запрос. Модульность и роли уже достаточны, чтобы вырасти без переписывания.
