# Сайберлос — прототип личного кабинета

Рабочий прототип по [TZ.md](TZ.md): электронный паспорт станции, гарантия 5/10(+) лет,
подтверждение монтажа дилером, платная подписка дилера, маркетплейс заявок «свой дилер → общий пул».

Стек: React (Vite, TypeScript) + Node/Express (TypeScript) + Prisma/SQLite.

## Запуск

Нужен установленный Node.js (LTS).

**1. Бэкенд** (порт 4000)

```bash
cd backend
npm install
npx prisma migrate dev
npm run seed
npm run dev
```

**2. Фронтенд** (порт 5173, проксирует `/api` и `/uploads` на бэкенд — см. `frontend/vite.config.ts`)

```bash
cd frontend
npm install
npm run dev
```

Открыть http://localhost:5173

## Демо-доступы (из `backend/prisma/seed.ts`)

## Оплата подписки дилера через Т-Банк

Подписка дилера (3 000 ₽/мес или 30 000 ₽/год) оплачивается через Т-Банк Acquiring API
(`backend/src/lib/tbank.ts`, `backend/src/routes/billing.ts`).

**Чтобы включить реальные платежи**, заполните в `backend/.env`:

```
TBANK_TERMINAL_KEY="..."
TBANK_SECRET_KEY="..."
BACKEND_PUBLIC_URL="https://ваш-публичный-домен"   # Т-Банк должен достучаться сюда webhook'ом
APP_BASE_URL="https://ваш-фронтенд"                 # сюда Т-Банк вернёт пользователя после оплаты
```

TerminalKey и SecretKey выдаются в личном кабинете Т-Банк для бизнеса (раздел «Эквайринг» →
подключение API). Для локальной разработки `BACKEND_PUBLIC_URL` с `localhost` не подойдёт —
Т-Банк не сможет достучаться до вебхука снаружи; на время теста можно прокинуть туннель
(например, ngrok) и указать его адрес.

**Если TBANK_TERMINAL_KEY/TBANK_SECRET_KEY не заполнены** (как по умолчанию в этом репозитории —
ключи не выданы), подписка работает в тестовом режиме: активируется мгновенно без реального
списания, весь остальной прототип при этом работает как обычно.

Что реализовано на уровне API Т-Банк:
- `Init` с `Recurrent=Y` для помесячного тарифа — Т-Банк сохраняет карту (`RebillId`)
- `POST /billing/tbank/webhook` — приём уведомлений о статусе платежа с проверкой подписи (SHA-256)
- `GET /dealer/subscription/status/:orderId` — подстраховка на случай, если webhook ещё не дошёл
  (дилер возвращается со страницы оплаты, фронтенд опрашивает статус через `GetState`)
- `POST /dealer/subscription/renew` — продление помесячной подписки по сохранённой карте
  (`Charge` по `RebillId`, без повторного ввода данных карты)

Токен подписи (`Init`/`Charge`/webhook) проверен на реальном API-эндпоинте `securepay.tinkoff.ru`
(запрос с фиктивным TerminalKey корректно отклоняется с осмысленной ошибкой, что подтверждает
правильность структуры запроса и алгоритма подписи) — полноценный сквозной тест возможен только
с настоящими TerminalKey/SecretKey.

## Смена домена (подготовка к реальному хостингу)

Сейчас всё настроено на `localhost`. Чтобы перевести на настоящий домен, меняются только
переменные окружения — код трогать не нужно.

Полный пошаговый план разворачивания на боевом сервере (VPS, Nginx, Postgres, HTTPS,
PM2) — в [DEPLOY.md](DEPLOY.md). Ниже — только про сами переменные окружения.

**1. Бэкенд** (`backend/.env`):

```
APP_BASE_URL="https://app.cyberlos.ru"        # адрес фронтенда — Т-Банк вернёт сюда после оплаты
BACKEND_PUBLIC_URL="https://api.cyberlos.ru"  # адрес ЭТОГО бэкенда — сюда Т-Банк шлёт webhook
CORS_ORIGIN="https://app.cyberlos.ru"         # какому домену фронтенда разрешено ходить в API
JWT_SECRET="..."                               # обязательно замените на длинную случайную строку
```

**2. Фронтенд** — нужен, только если фронтенд и бэкенд на *разных* доменах и между ними нет общего
реверс-прокси (если прокси есть и `/api`, `/uploads` проксируются на бэкенд под одним доменом с
фронтендом — этот шаг не нужен, всё заработает и без него):

Создайте `frontend/.env` (см. `frontend/.env.example`):

```
VITE_API_BASE_URL="https://api.cyberlos.ru"
```

и пересоберите фронтенд (`npm run build`) — значение зашивается в сборку на этапе билда,
runtime-переключение (без пересборки) не предусмотрено.

**3. На что ещё обратить внимание при переезде с localhost:**
- **SQLite** (`backend/prisma/dev.db`) — файл на диске бэкенда; на многих хостингах (serverless,
  контейнеры без persistent-диска) он не переживёт перезапуск. Для прод-хостинга разумно перейти на
  Postgres — меняется только `DATABASE_URL` в `backend/.env` и `provider` в `prisma/schema.prisma`.
- **`backend/uploads`** (фото ТО, логотипы дилеров) — тоже локальный диск бэкенда; при нескольких
  инстансах или serverless-хостинге стоит вынести в объектное хранилище (см. TZ.md, раздел 11).
- **T-Бank** — TerminalKey/SecretKey и реальный `BACKEND_PUBLIC_URL` (см. раздел выше) — без
  публичного адреса вебхук не дойдёт и статус оплаты не обновится автоматически.

## Что реализовано (MVP из TZ.md, раздел 15)

- Регистрация/вход (email+пароль), три роли: клиент / дилер / админ
- Регистрация станции клиентом + подтверждение дилером (даты монтажа и ввода в эксплуатацию)
- Расчёт гарантии «на лету» (`backend/src/lib/warranty.ts`): 5 лет база → 10 лет при регистрации →
  +шаг за каждое вовремя подтверждённое ежегодное ТО → откат к базовым 5 годам при нарушении графика
- Электронный паспорт станции с историей ТО и фото до/после
- Фиксация ТО дилером и резервный сценарий — запрос клиента с фото на подтверждение дилером
- Платная подписка дилера через Т-Банк (Init/webhook/GetState/рекуррентный Charge) — 3 000 ₽/мес или
  30 000 ₽/год, с тестовым fallback-режимом без реальных ключей (см. раздел выше)
- Вызов мастера (авария/сервис) с геолокацией на карте (Leaflet/OpenStreetMap, без платных API-ключей),
  маршрутизация «свой дилер (24 ч) → общий пул региона»
- Админка: справочник моделей (данные из [docs/catalog.md](docs/catalog.md)), дилеры, реестр станций и заявок,
  ручное подтверждение ввода в эксплуатацию для случая шефмонтажа
- Ф.И.О. и регион клиента/дилера при регистрации (регион — автодополнение по списку субъектов РФ,
  `backend/src/lib/regions.ts`); заявка на выезд наследует регион из профиля клиента
- Автодополнение адреса и определение адреса по клику на карте — прокси к Nominatim/OpenStreetMap
  (`backend/src/lib/geocode.ts`, без платного API-ключа)
- Строгая региональная изоляция общего пула заявок — дилер видит только заявки своего региона
- Бесплатный пробный период дилера 14 дней с полным доступом, после — лента заявок блокируется
  до оплаты (подтверждение монтажа остаётся бесплатным всегда)
- Напоминание клиенту о плановом ТО за 5 дней до дедлайна (баннер в приложении + журнал уведомлений)
- Рейтинг и отзывы дилеров (1–5 звёзд после выполненной заявки, дилер может запросить отзыв у клиента),
  каталог официальных дилеров по региону с отзывами (`/dealers`)
- Адаптивная мобильная вёрстка: шапка сворачивается в гамбургер-меню на узких экранах
  (`frontend/src/components/Layout.tsx`), формы и карточки перестраиваются в одну колонку
- Виджет поддержки (плавающая кнопка) с чат-ботом на базе FAQ — отвечает на типовые вопросы про
  гарантию, регистрацию станции, ТО, вызов мастера, подписку дилера; при непонятном вопросе даёт
  контакты живой поддержки (`backend/src/lib/supportBot.ts`, история сообщений хранится в БД)
- Чат внутри заявки между клиентом и дилером (текст + фото/файлы), доступен с момента, когда заявка
  закреплена за дилером (`assigned_to_own_dealer`/`claimed`/`completed`) — `frontend/src/components/RequestChat.tsx`
- Уведомление клиенту сразу при принятии заявки дилером («заявка взята в работу»), плюс уведомления
  о новом сообщении в чате и о новой заявке дилеру (своей или в общем пуле) — `backend/src/lib/notify.ts`
- Непрочитанное подсвечивается красным на карточках заявок и красным счётчиком в меню (обновляется
  каждые 15 сек), с озвучкой через Web Audio API при появлении нового уведомления, пока вкладка открыта
- Настоящий Web Push (VAPID, `backend/src/lib/push.ts` + `frontend/src/sw.ts`) — системное уведомление
  приходит, даже если вкладка не в фокусе (в рамках работающего браузера); включается кнопкой-колокольчиком
  в шапке после явного разрешения пользователя

## Осознанные упрощения прототипа (не продовые решения)

- Интеграция с Т-Банк реализована по документированному протоколу, но не протестирована со сквозным
  реальным платежом (нет боевых TerminalKey/SecretKey) — фискализация чеков (54-ФЗ) и закрывающие
  документы для дилеров как ИП/юрлиц не проработаны (TZ.md, открытый вопрос №7)
- Email/push-уведомления не отправляются — только бизнес-логика, баннер в приложении и запись в БД
- Регион дилера/заявки — один субъект РФ целиком (без города/района/радиуса) — при большом объёме
  заявок в одном регионе может понадобиться более гранулярная маршрутизация (см. TZ.md, раздел 15)
- Геокодирование через бесплатный Nominatim без API-ключа — не рассчитан на серьёзную нагрузку
  (лимит ~1 запрос/сек по их usage policy), для продакшена стоит перейти на платный провайдер
- SQLite вместо продовой БД (Postgres) — переключается через `DATABASE_URL` в `backend/.env`
- Фото ТО хранятся локально на диске бэкенда (`backend/uploads`), не в облачном хранилище
- Бот поддержки — совпадение по ключевым словам (без внешнего LLM API и ключей), покрывает основные
  темы о сервисе; на вопросы вне FAQ отвечает вежливым fallback с контактами живой поддержки
- Чат заявки и счётчики непрочитанного обновляются поллингом (раз в 6–15 сек), а не по WebSocket/SSE —
  задержка в пределах интервала опроса, без постоянного соединения
- Web Push работает, пока запущен браузер пользователя (даже в фоне) — это стандартное поведение
  Push API; полностью закрытый браузер уведомление не покажет, это ограничение платформы, а не прототипа
- Вложения в чате — фиксированный список форматов (изображения, pdf, doc/docx, xls/xlsx, txt, zip),
  до 15 МБ на файл; без антивирусной проверки содержимого (см. `backend/src/routes/uploads.ts`)

Эти пункты соответствуют открытым вопросам в [TZ.md](TZ.md), раздел 13.
